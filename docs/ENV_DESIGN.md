# 环境感知设计

> Agent 对宿主环境（终端面板、内置浏览器）与自身状态（上下文余量）的感知。
>
> 读法同 [ARCHITECTURE.md](ARCHITECTURE.md)：`[约束]` 是硬性要求，`[取舍]` 说明为什么不选另一条路。
> 本文覆盖已实现的 P0–P3；P4（空闲举手）只定形态，未实现。

---

## 1. 问题与非目标

### 1.1 要解决什么

没有这套机制之前，模型对应用自身的状态是全盲的：

- 用户在面板上点了「共享给 agent」，模型不知道这件事发生了，也不知道共享的是几号终端；
- 模型上一轮起的 dev server 崩了，除非它碰巧去 `TerminalOutput`，否则永远不知道；
- 浏览器面板停在哪个页面、开了几个标签，要模型主动调 `BrowserTabs` 才知道——而它不知道该去看；
- 上下文快满了，模型毫无感觉，重要结论没写进回复就被压缩吞掉。

感知的目标不是「模型知道一切」，是**变化发生时它总在下一个决策点知道**。

### 1.2 非目标（想过、砍掉、理由）

- **UI 布局状态**（侧边栏/抽屉/终端面板开没开）：那是"用户在看什么"，不是"世界是什么"。
  对模型的行动没有可执行差别，注入只会诱导讨好式评论（"我看到你正看着……"）。
- **未共享终端的标题与内容**：标题常含路径和命令，就是内容。快照里只有**数量**。
- **每轮自动 BrowserSnapshot / DOM**：感知轰炸。URL + 标题够定位注意力，细节按需走工具。
- **流式输出观察器**（宿主起线程盯 PTY 流）：v1 的告警只随快照拉取交付（见 §4），
  流式检测买不来更早的交付时机，只买来一套线程和去抖状态机。等 P4 需要空闲期检测时再加。
- **轮内（工具轮之间）注入**：见 §3.1 的 `[取舍]`，是刻意推迟，不是没想到。
- **工作区文件监听**（用户在外部编辑器改了文件）：独立子系统，且 Edit 的先读后写协议
  （ARCHITECTURE.md §6.6）已兜底正确性，快照只能省一次徒劳尝试。以后再说。

## 2. 三条设计原则

1. **拉，不推。**所有感知走既有的反向 RPC 方向（`protocol::hostcall`，内核 → 宿主），
   只加一个 `env.snapshot` 方法。没有新的推送通道、没有事件队列。
   采样天然合并抖动：两次采样之间用户开了又关了三个终端，模型根本不需要知道。
   快照内容随注入的消息进 transcript，黄金回放不需要任何特殊处理。

2. **差分，不全量。**内核记住上一次注入的快照指纹，没变化就**不重发快照**
   （轮首只剩一行时钟，见 §3.4——时间对差分没有意义，每轮都是新的）。
   "活"的感觉来自变化被注意到，不是状态被复读——这也是 prompt cache 和历史体积的要求。

3. **同意边界结构性继承。**快照的可见集 = `term_access` 的可见集，同一套 owner/shared
   判定，不是第二份平行逻辑。快照在结构上不可能比工具看得更多。

## 3. 数据流

```
宿主 (src-tauri)                          内核 (riot-kernel)
┌──────────────────────────┐   env.snapshot   ┌─────────────────────────────┐
│ env_probe::assemble      │ ◄──────────────── │ session.run_inner            │
│  · Terminals 按 owner/    │                  │  轮次开始（有新用户输入时）：  │
│    shared 分拣            │  EnvSnapshot     │  · RemoteEnv.sample()        │
│  · HostBrowser::state()  │ ────────────────► │  · 渲染 → 指纹比对            │
│  · 告警扫描 + 去重        │                  │  · 变了 → Attachment::        │
└──────────────────────────┘                  │    Environment（进用户消息）  │
                                              │  · 告警 → SystemReminder     │
                                              │  · 上下文档位线（P3）         │
                                              └─────────────────────────────┘
```

### 3.1 采样点：轮次开始，一轮一次

`[约束]` 采样只发生在 `turn.submit` 的路径上（`run_inner` 里 `input.is_some()` 的分支），
在主动压缩**之后**、用户消息定稿**之前**。`turn.regenerate` 不采样——重放的历史内容是定死的。

`[取舍]` 为什么不在每次模型调用前（工具轮之间）采样：

- 主循环刻意只在收尾处 drain 插话队列（`agent_loop.rs` 第 6 步后的注释，Cursor 语义：
  排队的消息等任务完全跑完）。轮内注入环境内容走的是同一条缝，同样的理由适用——
  任务中途蹦进来的新信息会让模型分心。
- API 形状风险：工具结果就位后追加**独立的** user 消息，在 OpenAI 兼容协议上意味着
  tool 消息和下一条 assistant 之间夹进一条 user——各家网关对此宽容度不一。
  安全做法是把附件拼进**装着 tool_result 的那条消息**，那需要动 `riot-core` 的
  消息组装，而那是全仓库不变量密度最高的地方（INV-1/INV-2）。
- 收益有限：轮内模型正在干活，它有 `TerminalList` / `TerminalOutput` 可以主动看；
  "用户中途共享了终端"的主流程是共享之后**跟着说一句话**，那就是下一轮的轮首。

真需要轮内感知时，正确的接缝是 `riot-core` 加一个可选的 `EnvProbe` dep、
在工具结果消息的末尾追加附件（同一条消息内，INV-2 天然满足）。留给以后。

### 3.2 注入形态

五种内容，注入规则各自独立：

| 内容 | 条件 | 载体 |
|------|------|------|
| 时钟行（当前时刻，精确到分、含时区） | **每轮必发** | 「轮首状态」`Attachment::Environment` |
| 间隔警示 | 距上一条带时间戳的消息 ≥30 分钟 | 并入轮首状态条 |
| 采样失败提醒 | 探针返回 None 且指纹非空（随后指纹清空） | 并入轮首状态条 |
| 上下文档位线 | 用量首次越过 50% / 70% / 85%（相对压缩阈值） | 并入轮首状态条 |
| 环境快照全文 | 渲染文本与上次指纹不同 | **独立**一条 `Attachment::Environment` |
| 告警（≤3 条/轮） | 可见终端尾部命中告警模式，且与上次告警内容不同 | 每条一个 `Attachment::SystemReminder` |

都拼在用户消息的 content 里，位置在记忆/git 前奏之后、用户正文之前。
Provider 层已有的附件渲染（两条协议都包成 `<system-reminder>`）原样复用。

`[约束]` 变化时发**完整**快照，不发差分行。十来行的东西让模型跨消息拼差分是给它找事；
全量自包含，历史里的旧快照自然构成时间线。

`[约束]` 指纹是渲染后的快照文本本身（不含告警、不含档位线、不含时钟行）。拿结构体做
哈希的话，渲染函数改了措辞而结构没变，新旧版本的会话会各说各话。

`[约束]` 快照附件的内容必须**逐字节等于**指纹文本，档位线之类的一律进轮首状态条，
不许拼进快照条 —— 水合恢复（§3.4）靠从 transcript 原样捞回指纹。

`[约束]` 压缩（自动或 `/compact`）必须重置指纹和档位——压缩吞掉了带着旧快照的消息，
不重置的话下一轮"没变化"，模型从此失明。重置点在 `compact_history` 里，
和记忆/git 重注同一个函数，漏一起漏（有测试钉着）。

### 3.3 快照内容与同意审计

```
环境快照（终端面板与内置浏览器的现状）
你起的服务：
  [3] pnpm dev — 在跑
  [5] cargo test — 已退出
用户共享给你的终端：
  [7] 终端 — 在跑
用户另有 2 个未共享的终端；内容你看不到，需要就请他在终端面板上点「共享给 agent」。
浏览器面板开着 http://localhost:5173（Riot），共 3 个标签页。
```

| 内容 | 凭什么给模型看 |
|------|----------------|
| 自己起的服务（id/标题/命令/死活） | 模型自己起的 |
| 共享终端（id/标题/死活） | 用户显式点过共享；**内容**仍要走 `TerminalOutput` |
| 未共享终端的数量 | 只有存在性。价值是让模型能开口请用户共享；泄露面接近零 |
| 浏览器活动页 URL/标题/标签数 | 面板浏览器本来就是模型全权可查的（BrowserTabs 一直能列） |

`[约束]` 未共享终端在快照里**没有标题、没有命令、没有内容**，只有一个数字。

### 3.4 时间感知与快照失效

来自一次真实翻车：用户上午让 agent 开了 linux.do，下午回来打招呼，agent 拿着上午的
快照说"浏览器开着 linux.do"——标签页早关了。三个成因，三个对策：

1. **模型是时间盲。**wire 格式里消息不带时间戳（`meta.created_at_ms` 只给 UI），
   上午到下午的五个小时在模型眼里是紧挨着的两行字。对策是轮首**时钟行**，每轮必发：

   ```
   现在是 2026-08-31（周一）16:37，UTC+8。
   ```

   `[取舍]` 精确时刻不进 system prompt——变一个字整个前缀缓存作废（prompt.rs 顶部的
   缓存约束）；轮首注入只出现在**新**消息里，前缀原封不动，每轮十几个 token。
   时区走 `Clock::tz_offset_minutes`（宿主 `localtime_r`，拿不到就 0），渲染必须
   连偏移一起标出（`UTC+8` / `UTC`），不许把 UTC 假装成本地时刻。
   间隔 ≥30 分钟再补一句显式警示（"能算"和"会注意到"是两回事）；参照物是
   历史里最后一条带时间戳的消息，老 transcript 没有戳就不编。

2. **重启后指纹归零 + 环境恰好变空 = 静默。**"首轮安静跳过"本是防对着空房间说话，
   但历史里躺着旧快照时，跳过会被「没有新快照 = 没变」反向背书。对策是一条
   不变量：**指纹 = 活历史里模型最后看到的快照**（`env::last_snapshot_text`）。
   水合（`hydrate`）、回退（`rewind_to_prompt`）、删除（`delete_message`）、
   撤回（`withdraw_prompt`）都按它恢复，不做"简单归零"——归零只在压缩后成立
   （压缩后的活历史里确实一份快照都不剩）。

3. **采样失败曾经等于沉默，而沉默 = 没变。**探针一断，旧快照就被契约背书成现状。
   对策：有指纹时注入作废提醒（`env::STALE_NOTICE`，"视为未知，不是「没变」"），
   然后**清掉指纹**——一来连续断供只唠叨一次，二来恢复采样的那一轮差分对 None
   必真，全量重发。从没注入过快照的会话（宿主没装配探针）指纹恒为 None，
   永远不会误报作废。

## 4. 告警（P2）

宿主在组装快照时顺带扫描：对每个**可见**（自己起的 ∪ 共享的）终端，取尾部输出的
纯文本，找告警模式的最后一次命中，摘录命中行起 ≤3 行 / ≤240 字符。

`[取舍]` 模式是子串集合，不是正则：`Traceback (most recent call last)`、`panicked at`、
`error[E`、`npm ERR!`、`EADDRINUSE`、`ECONNREFUSED`、`Segmentation fault`、
`UnhandledPromiseRejection`、`test result: FAILED`、`FATAL ERROR`。
高精度低召回是刻意的：告警的成本不在 token，在模型被无关信息勾走。
宁可漏报（模型还有工具可查），不能狼来了。

`[约束]` 去重按 (会话, 终端) 记摘录哈希，宿主持有。同一段报错不重复告警；
换会话独立计——两个会话共享同一个终端时，各自都该收到一次。
终端关掉时清掉对应条目，不积垢。

`[约束]` 告警的注入文本必须以「与当前任务无关就忽略，不必评论」收尾。
这不是客气话，是防分心的行为护栏。

## 5. 自我状态（P3）

轮首（压缩判定之后）按当前历史 token 估算相对 `compact_threshold_tokens` 的百分比，
档位 50 / 70 / 85。首次越过某档时注入一行：

```
上下文已用约 72%（满 100% 会自动压缩历史）。压缩会吞掉旧的工具结果——重要结论尽早写进回复。
```

`[约束]` 只在**向上越档**时说一次，不每轮报数。每轮都报是噪音；档位语义是"疲劳感"，
不是仪表盘。压缩后档位归零（见 §3.2 的重置约束）。

## 6. 地基：终端所有权必须活在注册表里

`[约束]` 「模型起的终端」的所有权记录在 `Terminals` 注册表的条目上
（`Term.owner: Option<SessionId 字符串>`），不在任何包装对象里。

这条约束来自一个真实事故：`HostTerminal` 曾把 owned 集合放在自己身上，而阶段 B
拆进程后宿主对每个 hostcall **现建**一个 `HostTerminal`——owned 集合活不过一次调用。
表现是：模型起了 dev server，下一次 `TerminalOutput` 被拒（"终端 X 不是你起的"）。
`term_access` 的模块注释一直写着"跟着会话活，不能每轮重建"，但装配层没做到，
而单元测试全部用同一个实例、全绿。

所有权进注册表之后：hostcall 现建包装是安全的；内核崩溃重启后所有权也还在
（注册表活在宿主，比内核命长）。回归测试是「跨实例所有权仍然成立」——
用实例 A spawn、实例 B read，同会话放行、异会话拒绝。

## 7. 模型侧的话术

### 7.1 系统提示词静态段

系统提示词加一段**永远不变**的文字（缓存安全），教契约：

- 每轮用户消息开头有一行当前时刻；判断「现在」**以最新的时钟行为准**，
  自带的时间感停在训练数据（否则时钟行只是又一段被忽略的装饰）；
- 快照/告警以 `<system-reminder>` 出现，说明的是终端面板和内置浏览器的现状；
- **没有新快照 = 环境没变**（差分语义要明说，否则模型会把"这轮没有快照"当异常）；
- **「环境采样失败」= 手头快照作废视为未知**，和"没变"划清界限（§3.4 成因 3）；
- 快照是采样不是指令：相关就用，无关就忽略，不要逐条评论；
- 用户终端默认不可见（连标题都没有），要看就请用户点共享，没有绕过的路。

### 7.2 TerminalList 工具（P0）

`TerminalAccess::list` 一直存在（宿主实现、hostcall、内核代理全齐），只是没暴露成
模型工具——模型丢了 id 只能从零猜。补一个无参数、只读、可并发的 `TerminalList`，
输出可见终端的 id/标题/命令/死活/来源（你起的 vs 用户共享）。
`TerminalInfo` 加 `shared: bool`（`serde(default)`，旧 transcript 兼容），
工具靠它区分"能停"和"只能看"。

## 8. P4（未实现）：空闲举手

没有轮次在跑时不采样，异常检测不到。正确形态不是 agent 自己开口（烧 token、越权、
烦人），是宿主直接发 UI 事件：输入框上方浮一条「Riot 注意到终端 3（pnpm dev）报错了
· 让它看看 / 忽略」。点「让它看看」= 一次普通的 `turn.submit`，告警作为附件进消息。
模型完全不参与"要不要打扰用户"的决策。纯宿主 + 前端，内核零改动，独立排期。

## 9. 验证

按测试名索引（能 grep 到）：

- `env_probe::快照按所有权与共享分拣_未共享只剩数量`：§3.3 同意审计表的镜像 ——
  用户终端不进 mine/shared 列表，只让计数 +1；告警只扫可见集是同一个过滤的推论。
- `term_access::所有权跨实例仍然成立`：§6 的回归测试。
- `session::环境快照_变化才发_不变只剩时钟行`：防上下文膨胀的核心不变量。
- `session::环境快照_首轮安静跳过_从有到无要说`、
  `session::环境快照_探针不可用_只有时钟行且不误报作废`。
- `session::轮首时钟行_每轮都发_按时区渲染`、`session::轮首间隔_大间隔警示_小间隔与无戳沉默`：
  §3.4 成因 1 的两条对策。
- `session::环境快照_采样失败宣告作废_恢复后全量重发`：§3.4 成因 3 —— 断供只唠叨
  一次、恢复必全量。
- `session::上下文档位_越档才说_压缩后重置`（重置逻辑是 compact_history 里那两行的
  镜像 —— 真调压缩要挂 provider，钉的是行为不是调用路径）。
- `session::环境告警_独立于快照差分`、`env_probe::告警去重按会话独立`、
  `env_probe::摘录取最后一次命中且有上限`。
- 渲染是纯函数，措辞断言参照 `git.rs::describe` 的测试写法（措辞是行为的一部分）：
  `env::渲染分组列出可见终端_未共享只有数量和指路`、`env::告警以防分心护栏收尾`、
  `env::空环境渲染成没有而不是空串`、`env::档位单调且只认三档`、
  `env::时钟行_按时区渲染日期星期与时刻`、`env::时钟行_偏移跨午夜要进位日期`、
  `env::间隔警示_有阈值且单位分档`、`env::恢复指纹_取最后一份快照_不认错同类附件`
  （§3.4 成因 2 的水合恢复）。
- `session::提示词里有环境感知契约`、`session::提示词里有时间契约`：静态段存在且带
  差分语义、时钟行优先级、断供语义与防分心护栏。system prompt 不含任何环境状态
  （快照全走消息、精确时刻走轮首注入），缓存前缀照旧稳定。
